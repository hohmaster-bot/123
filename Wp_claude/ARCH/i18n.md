# Texts by key (D4, D24, package 21)

- Files: `wp/i18n/ru.json`, `wp/i18n/en.json`: flat `key -> text` (UTF-8 data; code stays ASCII). Keys are the ids
  the program already has, grouped by prefix: `reason.` (refusals), `warning.`, `settings.` (setting labels,
  descriptions, groups), `rules.` (rule constants), `catalog.kind.`, `catalog.field.`, `skill.`, `stat.`, `tier.`,
  `damage.`, `slot.`, `resource.`, `status.`, `feat.`, `ui.`, `mode.`, `panel.`, `theme.`.
- `wp/i18n/i18n.py`: `t(key, lang, **params)` (lang -> ru -> the key id; never raises), `{name}` and `{values[i]}`
  substitution, `plural(key, n, lang)` (ru one / few / many, en one / other), `text_for(error, lang)` for a
  CommandError (`reason.<id>` + its params), `language(app)` (app setting "language"), `strings(prefix, lang)`.
- The language switch is the app setting `language` (settings_set). The game is Russian for now; English may be
  partial.
- What the owner typed (names, descriptions) is never translated. A catalog entry may carry `name_i18n`
  `{lang: name}`; `catalog_view.display_name(entry, lang)` falls back to `name`.
- Coverage: `python Wp_claude/tools/i18n_report.py` writes `Wp_claude/TRANSLATION_TODO.md` (missing ru / en keys by
  prefix, unused keys); `--fill-en` adds missing English refusal texts made from the English messages in the code.
  A test fails when a needed key is neither in ru.json nor in the TODO file, or the TODO file is out of date.
- The needed keys are collected by `wp/i18n/keys.py` from the code (CommandError reasons) and the data (schemas,
  catalogs, registry); nothing is typed twice.
