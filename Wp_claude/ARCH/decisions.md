# Decisions
Status: A = accepted by owner, P = proposed (needs owner OK), X = superseded.

| id | status | decision | why |
|---|---|---|---|
| D1 | A | No save migrations, ever. New format may break old saves. Old characters are not carried over; create new ones. Package 16 (owner): on load unknown fields are dropped; anything not working is unfinished work or a bug. | Owner, 2026-11-17. Simplicity. |
| D2 | A | UI toolkit: PySide6. | LGPL; overlay prototypes already on PySide6; Qt has tray, frameless, opacity built in. |
| D3 | A | Two exclusive modes: Classic (full-screen sheet, Alt-Tab/hotkey) and Overlay (light, always-on-top panels). Never shown together: enabling one disables the other. Each has its own independent settings. Both have an edit mode that works differently. Split removed. Superseded by D20 (Classic and Lite). | Owner, 2026-11-17. See `surfaces.md`. |
| D4 | A | i18n: every UI string in locale files; code is ASCII only. Note 2026-11-20 (owner): the UI language switches RU / EN; texts come from `wp/i18n/ru.json` and `wp/i18n/en.json` (one table per language; the reason ids of refusals are the keys). For now the game stays single-language (Russian); the files and the switch come with Phase 3 or later. | Owner. RU/EN switch; PowerShell can no longer corrupt code. |
| D5 | A | Commands are the only mutation path: UI -> `dispatch(cmd)` -> validate -> mutate -> action_log -> `changed` signal. Resources get two ops: `restore` (gameplay: regen, heal, rest, tick; clamps to max) and `set` (manual/overfill; no clamp, flagged "over max"). Exceeding max is allowed (RULES/resources.md "Over max"). | One place for bounds, transactions, undo, refresh (A053, A059). |
| D6 | A | Store base values only; derived values computed on read. | A087 (max inflation), legacy display fields. |
| D7 | A | Stable ids for every entity (feats, spells, courts, buffs, chips...); no references by display name. The player never types an id: the program makes it from the name (transliteration, a number on a collision; `wp/model/ids.py`) [OWNER pkg 5]. | A045, A046, A088; renames orphan chip order/colors. |
| D8 | A | Docs for Claude in English; owner-facing docs in Russian. | Cyrillic costs noticeably more tokens. |
| D9 | A | Split core into domain modules; step 1 = mixins (`c.method()` calls unchanged), protected by tests. | Smaller files to read; no big-bang rewrite. |
| D10 | A | All new docs live in `Wp_claude/`; old docs go to `Wp_claude/archive/` later. | Owner. |
| D11 | A | One persistence service: validate, atomic temp+replace write, keep last good copy. | A063, A064, A065, A079. |
| D12 | A | Logic before UI. Exception: an early technical overlay spike (click-through, hotkey). | Owner; spike de-risks D3. |
| D13 | A | Three settings domains: character gameplay (in save), catalogs, UI profile (per user, not per character). Enabled catalogs: one list for the user (global). | A005, A014, A017; RULES/catalog.md. |
| D14 | A | One generic effect system for every sheet part (race, class, feat, item, injury, quirk, spell, buff): any effect can change any base parameter, with duration and charges (no combat-only condition: package 8). | RULES/buffs.md, RULES/index.md "Cross-cutting". |
| D15 | A | Damage pipeline per damage component (by type): 1) percent reduction (25/50/75 %), 2) flat reduction by damage type (DR = flat vs PHYSICAL; fire etc. are other types), 3) temp HP, 4) temp-HP analogs (e.g. race mana) in a configurable order, 5) HP + balance (only the part reaching HP). Integer damage, round UP. | RULES/resources.md "Damage pipeline"; classes_magic.md "Racial damage absorbers". |
| D16 | A | Weapon stores a list of parents (variety, group; a variety may sit in several groups). Combat basics bonus = max over the weapon and its ancestors, never a sum. | RULES/weapons.md "Combat basics"; baseline WPN-basics-nostack. |
| D17 | A | Item has two tabs of effects: "not activated" and "activated". Exactly one set acts, never both; no mode flag (an additive item repeats base effects in the activated tab). | RULES/gear.md "Item activation data"; baseline GEAR-item-tabs. |
| D18 | A | Pain from HP and all other derived values are computed on read, never stored. | RULES/resources.md "Pain"; D6. |
| D19 | A | Skill tiers normal / advanced / specialized are data; all prices come from the formulas in RULES/skills.md. | RULES/skills.md; avoids hard-coded tier logic. |
| D29 | A | Input validation by declared types: every command parameter has a kind (wp/commands/data/params.json, else the signature default) checked before the command runs; a command result must fit the stored dataclass types (wp/storage/typecheck.py), the same check the loader runs; other errors become invalid_value. The journal has two modes (app setting journal_mode): short keeps the newest lines, full moves the oldest block into an append-only archive per character (<name>.history.jsonl with a date index) that travels with the character. | Owner, 2026-11-25, package 27 (review 5). ARCH/app_layer.md "Journal", ARCH/settings.md. |
| D28 | A | Actions are a resource (base 3 per turn, effects actions_max add, refilled by the tick and the end of combat; costs are shown, never spent automatically); a flask display style with segments; experience is a log with notes, a goal and a level history (no threshold). | Owner, 2026-11-24, package 26. RULES/combat.md, narrative.md, UI_WISHES.md "Classic screen v1". |
| D27 | A | Class v0 is data (catalog kind classes), one class, a snapshot on the character; BAB and base saves derived from class + level with a hand override; undo is a bounded stack of previous states in the Session; drives carry level notes and a principle. | Owner, 2026-11-24, package 25. ARCH/classes.md. |
| D26 | A | Hands have sides (left / right; Item.hand, sides by order when not stored); AC cells return a list of variants; the defence cell rules (parry cells, Dex-loss cells, shield cells per type, ranged and parry, the cancel chance, the default shield hand) are rule constants editable per character and changed by effects (effect cells). | Owner, 2026-11-24, package 24. ARCH/doll_hands.md, ac_variants.md. |
| D25 | A | The UI talks only to the Session (wp/app/session.py): views by panel id, commands through session.dispatch with topics to refresh; read caches live outside the data and are cleared by every command. | Owner, 2026-11-23, package 23. ARCH/app_layer.md, view_contract.md. |
| D24 | A | Texts by key files (wp/i18n/ru.json, en.json) with the fallback lang -> ru -> key id; themes as token data (two layers, QSS built by pure Python); a panel registry as data that layout profiles are checked against. No Qt code before the UI phase. | Owner, 2026-11-23, package 21. ARCH/i18n.md, themes.md, panels.md. |
| D23 | A | Every game-rule number is data (wp/rules_data/constants.json); code reads it only through wp/rules_data/rules.py (ref / const / default); a character overrides any constant in rules_settings.constants (set_rule_setting); a test forbids new rule literals in code. | Owner, 2026-11-23, package 20 (review 4 F15). ARCH/constants.md. |
| D22 | A | Settings are data with a schema (settings_schema.json); three domains: game rules (Character.rules_settings), character-bound (Character.char_settings), application / UI (global app_settings.json, two layers, atomic save); layout profiles per mode (Classic, Lite), many each, one active; quick buttons with macros of existing commands; an image registry. Commands are the only mutation path. Refines D13. | Owner, 2026-11-23, package 19. ARCH/settings.md. |
| D21 | A | Catalogs are single self-contained JSON files (one per kind) with two layers (shipped read-only, user with overrides and tombstones) and catalog commands as the only mutation path; the UI later reads them through the catalog view and writes them only through catalog commands. | Owner, 2026-11-23, package 18. RULES/catalog.md "Catalog files". |
| D20 | A | The UI has exactly TWO modes: "Classic" and "Lite". The old "split" mode is removed. The overlay is NOT a separate mode: it lives inside Lite (Lite = overlay; it is switched on there). Replaces D3. | Owner, 2026-11-20. See `surfaces.md`. |
