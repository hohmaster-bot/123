# PROMPT.md — онбординг бота (T-ONBOARD)

> Роль: как бот **задаёт вопросы** перед задачей, чтобы **не** **делать** **не** **то**.
> При **конфликте** — **прав** `CONTRACT.md` / `character.schema.json`.

## 1. Входной пакет (что прочитать в начале)
Перед началом любой работы бот **обязан** прочитать эти файлы (в этом порядке), чтобы свериться с реальностью:
1. `PROJECT_MAP.md` (где что лежит).
2. `CONTRACT.md` (правила ответа и работы с JSON).
3. `character.schema.json` (истина по полям).
4. `GLOSSARY.md` (сокращения и пути).
5. `TECH.md` (текущие приоритеты и задачи).

Если для задачи не хватает какого-то файла кода (например, нужно менять `gui_combat.py`, а его нет) — **запросить у пользователя**.

## 2. Порядок обновления документации
Если правки в коде затронули архитектуру, поля или логику, документация обновляется **строго в таком порядке**:
1. `character.schema.json` (если добавили новое поле).
2. `GLOSSARY.md` (описание нового поля/пути).
3. `PROJECT_MAP.md` (новые функции или файлы).
4. `TECH.md` (статусы задач).
5. `LOG.md` (что именно сделано).
6. `PROMPT.md` (только если изменился сам процесс).

## 3. Как задавать вопросы
1. **Один вопрос за раз.** Не списком.
2. **С рекомендацией.** «Я бы предложил X. Согласен?» — не «что ты хочешь?».
3. **Не спрашивай то, что есть в** `PROJECT_MAP`, `CONTRACT`, `schema`, `GLOSSARY`, `TECH`.
4. **Цель — вскрыть допущение**, не собрать пожелания.
5. **Минимум 5 вопросов. Цель — 10.** Стоп, когда ясно.
6. **После каждого ответа** — **обнови** **понимание** (0–100%).
7. **Перед патчем** — **план** (1–2 строки). **После «ок»** — патч.

## 4. Формат ответа
- **Точечные патчи**: «найди X → замени Y». Без «вот весь файл», если не просят.
- Сначала **план** (1–2 строки). После «ок» — патч.
- Если меняем схему — **сначала** предложи правку `schema`, дождись «ок», потом код.

## 5. Чек-лист перед патчем
1. Поле есть в `character.schema.json`? (если нет — §2 `CONTRACT`)
2. Путь в JSON указан полностью?
3. Legacy/CALC учтены?
4. `training.purchases` не трогаем?
5. `settings` не трогаем?
6. Формат — точечный патч?
7. `python _check.py` → **ALL OK**?
